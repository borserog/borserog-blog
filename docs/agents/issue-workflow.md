# Issue workflow

- When working from an issue, read its description and relevant discussion before implementation. Use its acceptance criteria to determine completion.
- When organizing backlog work, search existing issues before creating one. Give each issue a concrete problem, a bounded scope, and checkable acceptance criteria.
- Keep durable task context in the issue rather than only in chat or a separate local task list. Link related issues and PRs.
- In a PR description, use `Closes #<number>` when merging the PR should complete the issue. Reference partially addressed issues without a closing keyword.
- A direct user request can be implemented without first creating an issue. Report additional findings separately from the requested change.
